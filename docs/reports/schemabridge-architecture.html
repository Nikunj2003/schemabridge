01The architecture in one sentence

A migration is a durable, policy-governed state machine whose model calls are verified, whose judgement calls interrupt for a person, and whose every material action is retained under an explicit workspace and expiry policy.

The system is deliberately conservative. It automates rules and transformations that have a documented basis, asks a model only to propose a bounded answer to real semantic uncertainty, and escalates when competing evidence makes a silent choice unsafe. A reviewer resumes from exactly the saved state; a later approved rule helps a later run rather than rewriting history.

What is guaranteed: durable pause/resume, actor provenance, bounded processing, explicit workspace scope, and idempotent destination effects when the destination honours its supplied key.
What is not claimed: semantic proof from type checks, exactly-once network delivery, automatic rollback, work that continues with every browser closed, or production readiness for real personal data.

02One origin, separate trust boundaries

The browser sees one application; authority changes at the API boundary.

Personal workspace

A verified issuer and subject become an opaque owner id. Data is isolated, retained 168 hours, and receives 20 migration starts per India calendar day.

Shared guest workspace

No bearer token is an explicit choice of one fixed guest owner. Its visibility is intentional, with 48-hour retention and 100 starts shared across guests.

03The decision path never gives the model the last word

Every transition has a specific authority and an audit event.

06Operational contract

Ownership, visibility, and cross-workspace access are intentional rather than accidental consequences of a browser session.

Identity resolution

Auth0 access tokens are checked for issuer, audience, RS256 signature, expiry, and rotating JWKS. A valid subject becomes a non-PII storage owner. Bad tokens receive a 401; they never see guest data.

Operator observability

End-user tokens cannot list every run. `/api/observability` requires a separate server-only header secret, checked in constant time, and can join run audit evidence with persisted model exchanges.

Safe delivery

Delivery uses outbound HTTP, bounded retry classification, and a stable idempotency key. The design protects effects across a lost response without pretending the network provides exactly-once delivery.

Service diagnosis

`/api/health` reveals configuration booleans without credentials. `/api/docs` and `/api/openapi.json` document the application contract. Health is not a live probe of every external dependency.
